# ลดโควตา Supabase: บีบอัดรูปปก (perf/compress-covers)

## อ่านจากฐานจริง (SELECT อย่างเดียว เมื่อ 22 พ.ย. 2569)
- bucket `resource-covers`: 82 ไฟล์ รวม 51.9 MB เฉลี่ย 633 KB ใหญ่สุด 2.7 MB
- ใช้จริงกับสื่อ 65 ชิ้น: PNG ใหญ่ ~2 MB 7 ชิ้น, JPG/WebP 150–630 KB ส่วนใหญ่
- cacheControl: 77 ไฟล์ = 1 ชั่วโมง, 5 ไฟล์ = no-cache

## สิ่งที่เปลี่ยนในโค้ด
1. อัปโหลดรูปปกใหม่จากหน้าแอดมินตั้ง `cacheControl` 1 ปี (ชื่อไฟล์ไม่ซ้ำและไม่เขียนทับ จึงปลอดภัย)
2. ตัวตัดรูปปก (CoverCropper) ส่งออก WebP กว้างไม่เกิน **800px** คุณภาพ **0.8** (เดิม 1448px / 0.85)
3. เครื่องมือใหม่ในหน้าแอดมิน → จัดการสื่อ: **"บีบอัดรูปปกเดิม"**

## เครื่องมือ "บีบอัดรูปปกเดิม"
- ใช้สิทธิ์แอดมินที่ล็อกอินอยู่ ไม่ใช้ service key ไม่มีสคริปต์ที่ต้องรันเอง
- กด "ตรวจรายการ": แสดงสื่อที่ปกอยู่ใน `resource-covers` ใหญ่เกิน 150 KB และยังไม่เคยบีบอัด พร้อมขนาดเดิมและขนาดที่คาดว่าเหลือ (ตัวเลขคาดการณ์)
- หลังตรวจรายการ เลือกทำ **1 / 5 / 20 / ทั้งหมด** รูปต่อรอบ (เริ่มต้น 1) โดยเริ่มจากไฟล์ใหญ่สุดก่อน รูปที่บีบอัดแล้วจะไม่อยู่ในรอบถัดไป
- กด "ดาวน์โหลด CSV สำรองของรอบนี้" ซึ่งมีเฉพาะรูปที่เลือกรอบนั้น แล้วตรวจว่าไฟล์อยู่ในเครื่องและติ๊กยืนยัน ปุ่ม "บีบอัด N รูป" จึงกดได้ เปลี่ยนจำนวนหรือสแกนใหม่ต้องดาวน์โหลด CSV อีกครั้ง
- เครื่องมือทำทีละรูป: โหลดรูปเดิม → ย่อเป็น WebP ≤800px q0.8 → อัปโหลดไป `v2/<uuid>.webp` (แคช 1 ปี) → เปลี่ยนลิงก์ปกของสื่อนั้น → ล้างแคชหน้าเว็บตอนจบ
- รูปที่พลาดจะถูกข้าม ทำรูปถัดไปต่อ และสรุปท้ายงาน ไฟล์ใหม่ที่ไม่เล็กลงอย่างน้อย 10% จะไม่ถูกใช้
- จบรอบจะแสดงจำนวนที่ทำ ขนาดก่อน/หลังของรูปที่สำเร็จ จำนวนที่ยังเข้าข่าย และปุ่มย้อนกลับเฉพาะรอบนั้น; CSV ของแต่ละรอบใช้ย้อนกลับภายหลังได้
- **ไม่ลบไฟล์เดิม**
- การเปลี่ยนลิงก์ใช้ฟังก์ชันใหม่ `admin_set_resource_cover(resource_id, cover_url)` (migration **063**) ที่แก้ **เฉพาะ `cover_image_url`** ของสื่อชิ้นนั้น
  ไม่แตะ status, published_at, slug, สิทธิ์/แพ็ก, ลำดับ หรือช่องอื่น และไม่ได้เขียนสิทธิ์ซ้ำเหมือน `admin_save_resource`
  ผลกระทบข้างเคียง: ตาราง `resources` ไม่มีคอลัมน์ `updated_at` และไม่มี trigger (ตรวจจาก migration ทั้งหมดและอ่านจาก staging) จึงไม่มีอะไรถูกอัปเดตตามมา
- ฟังก์ชันตรวจ: ผู้เรียกเป็นแอดมิน/เจ้าของ → สื่อมีอยู่ → URL เป็น `https://…/storage/v1/object/public/resource-covers/<path>` (path ใช้ได้เฉพาะ ตัวอักษร ตัวเลข . _ - /) → **มีไฟล์ชื่อนั้นอยู่จริงใน bucket resource-covers ของโปรเจกต์นี้** (นี่คือสิ่งที่ผูกลิงก์กับโปรเจกต์นี้ โดยไม่เดาโดเมน)
- ก่อนเริ่ม (และก่อนย้อนกลับ) เครื่องมือเช็กว่า 063 ติดตั้งแล้ว ถ้ายังไม่ติดตั้ง จะหยุดทันทีโดยยังไม่ดาวน์โหลด/อัปโหลด/เปลี่ยนอะไร
- "ย้อนกลับ": คืนลิงก์เดิมของรอบนี้ หรือเลือกไฟล์ CSV สำรอง (รับเฉพาะลิงก์ของ bucket นี้) คืนเฉพาะสื่อที่ปกตอนนี้อยู่ใน `v2/`
